ALSA

AI-native project management web app. FastAPI, 31 database tables, 111 routes, vanilla JavaScript, PostgreSQL in production. Built solo over about five to six months, with AI-assisted development.

Problem

Teams share projects with different people at different levels, and adding AI means project data might leave the system. Both have to be controlled on the server, not in the interface.

Decisions

  • Access control has two layers: a workspace role and a level per project. Anything unknown is denied.
  • AI is off by default. The server checks the switch before the prompt is built, so with AI off no project data reaches the provider.
  • Integration tokens are encrypted at rest. A write without a key is rejected rather than stored as plain text.

What the public excerpt doesn’t cover

  • The route layer, the prompts and the frontend are private.
  • There is no CI/CD pipeline. Deploys go through the Render dashboard.
  • Tests for the project-access endpoints live in the private repository.

conflict-safe-notes

A zero-dependency reference implementation of optimistic locking (HTTP 409) and session recovery for a browser client. Only what Node.js ships with, no framework or database. Written separately and not taken from ALSA’s code; it shows patterns I use there.

33automated tests
3Node versions in CI
0runtime dependencies

Rules it follows

  • 409A save must name the version it was based on. A stale save gets a conflict and the latest note.
  • GETRetried when the network fails. Reading twice is harmless.
  • PUTNever repeated automatically, because it could apply twice.
  • 401When a login expires, the app says so once, keeps the unsent draft and restores it when the same user signs in again.

What holds up

  • 33 automated tests, including two simultaneous saves that must give exactly one 200 and one 409.
  • A test for a save whose response is lost on the way back.
  • Tests pass on Node 18, 20 and 22 in GitHub Actions.

What it doesn’t cover

  • Data lives in memory, and the login accepts any name.
  • Checked by hand in Chrome only, not with a real screen reader.
  • “Simulate another editor” plays the second person, so it is not proof with real concurrent users.
